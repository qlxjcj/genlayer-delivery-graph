The problem it solves

Most escrow primitives assume one deliverable with one verdict. Real paid work rarely arrives in one piece: it arrives as parts with dependencies, and a part that rests on a failed part was never deliverable at all. A plain escrow cannot express that. A graph can.

A payer funds a graph of work nodes. Each node carries its own escrow tranche, its own evidence window, and a list of literal markers it demands in its evidence. A node is released to the recipient only when every marker is found and every node it depends on was accepted. Otherwise its tranche goes back to the payer.

What the model does — and what it does not

The model never decides anything. There is no score, no opinion, no “supports”. Each node declares literal markers such as build passed or 99.9%, and consensus is asked for exactly one thing: the verbatim span of the evidence where each marker appears.

The code then decides, with a pure conjunction:

marker met    ⇔  marker found literally in the fetched text
              or  a quoted span that really occurs in the text
                  and really carries the marker

node accepted ⇔  every marker met  ∧  every dependency accepted

The second clause is the model’s one genuine contribution, and it is narrow: a renderer that drops a stray blank inside a word (buil d passed) defeats a literal search, and a verbatim quote catches it. The quote is checked against the text the contract itself fetched, so a model can only lose credit, never create it. An answer the contract cannot use credits nothing at all.

Fetching and quoting share one equivalence-principle block, so there is a single consensus point per settlement, and the verdict fields are computed in code inside that block — validators agree on the decision, not on the wording of a leader’s answer.

Three invariants

1. The evidence set is final before anything is judged

Every node has evidence_by. submit_evidence refuses at or after it, and settle refuses before it, so the set of sources provably cannot grow between the moment it is read and the moment money moves.

2. Every write enforces the same preconditions

All five writes load the same record and check the same things. A refusal never mutates anything, which is asserted byte for byte across every rejection path.

3. No unit of the escrow is ever stranded

create_graph refuses unless sum(tranches) == escrow exactly, so the split is settled before a single unit can move. Each tranche then has exactly one destination: the recipient if accepted, the payer if rejected or blocked. At close the contract balance is back where it started. 

accepted_total + rejected_total + blocked_total == escrow

Asserted on a graph where all four outcomes happen at once, and again on one where everything fails.

Lifecycle

NodeMeaning
OPENsources may be filed
FROZENthe set of sources is final
ACCEPTEDevery marker found, dependencies accepted — tranche to the recipient
REJECTEDa marker was not found, or no source could be read — tranche to the payer
BLOCKEDa dependency was not accepted — tranche to the payer

Settlement order is enforced by state, not by time: settle(n) requires every parent of n to already be settled.

API

Writes

MethodNote
create_graph(recipient, nodes)payable. nodes[i] = {id, label, parents, markers, sources, tranche, window}
submit_evidence(g, n, url)files a source. The contract fetches it itself at settlement — nobody can hand it a made-up document
settle(g, n)judges the node and moves its tranche immediately
cancel(g)payer only, only before any evidence is filed; refunds the escrow whole
close(g)marks the graph finished once every node is settled

Views

All return JSON strings, never a bare list or dict, because a float in a return value breaks calldata encoding on chain while direct mode stays green.

Testing

52 direct-mode tests in seven groups: creation, the freeze boundary, marker verification, the dependency gate, fund conservation, uniform write preconditions, and views. Direct mode does not track native value, so conftest.py installs two accounting hooks — payable value into the contract, emit_transfer out of it — so every payout assertion is a real balance change rather than a tautology.

There is deliberately no catch-all model mock: a call a test did not anticipate fails rather than silently returning something plausible.
